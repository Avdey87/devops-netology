## Задание 1.3 — Намеренные ошибки в блоке строк 29–42

### Исходный (закомментированный) блок

```hcl
resource "docker_image" "nginx" {
  name         = "nginx:latest"
  keep_locally = true
}

resource "docker_container" "1nginx" {
  image = docker_image.nginx.image_id
  name  = "example_${random_password.random_string_FAKE.resulT}"
  ports {
    internal = 80
    external = 9090
  }
}
```

### Ошибки и их суть

| № | Где | Ошибка | Суть |
|---|---|---|---|
| 1 | `resource "docker_container" "1nginx"` | Имя ресурса (локальное) **начинается с цифры** | В HCL идентификатор ресурса обязан начинаться с буквы или `_`. Terraform падает с `Invalid resource name`. |
| 2 | `${random_password.random_string_FAKE.resulT}` | Опечатка в имени ресурса: `random_string_FAKE` вместо `random_string` | Terraform чувствителен к именам — ссылка на несуществующий ресурс, `Reference to undeclared resource`. |
| 3 | `.resulT` | Опечатка в атрибуте: заглавная `T` вместо строчной | Атрибут называется `result` (в нижнем регистре). Terraform падает с `Unsupported attribute`. |

### Исправленный фрагмент

```hcl
resource "docker_image" "nginx" {
  name         = "nginx:latest"
  keep_locally = true
}

resource "docker_container" "nginx" {
  image = docker_image.nginx.image_id
  name  = "example_${random_password.random_string.result}"
  ports {
    internal = 80
    external = 9090
  }
}
```

После исправления:

```
$ terraform validate
Success! The configuration is valid.
```

## Задание 1.5 — Переименование контейнера в `hello_world`

В блоке `docker_container.nginx` изменено только имя **контейнера** (`name = "hello_world"`). Имя **образа** осталось `nginx:latest`.

```hcl
resource "docker_image" "nginx" {
  name         = "nginx:latest"
  keep_locally = true
}

resource "docker_container" "nginx" {
  image = docker_image.nginx.image_id
  name  = "hello_world"
  ports {
    internal = 80
    external = 9090
  }
}
```

Выполнено:

```bash
terraform apply -auto-approve
```

Terraform пересоздал контейнер (`name` — forceNew атрибут, переименовать на месте нельзя):

```
docker_container.nginx must be replaced
-/+ resource "docker_container" "nginx" {
      ~ name = "example_xjJMPvLy8ezYOiZG" -> "hello_world" # forces replacement
      ...
    }

Apply complete! Resources: 1 added, 0 changed, 1 destroyed.
```

Вывод `docker ps`:

```
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS          PORTS                  NAMES
ddc9e53c7627   b69ff87d4106   "/docker-entrypoint.…"   16 seconds ago   Up 16 seconds   0.0.0.0:9090->80/tcp   hello_world
```

### Опасность и польза `-auto-approve`

**В чём опасность.**
Ключ `-auto-approve` отключает интерактивное подтверждение `Do you want to perform these actions? Enter a value: yes`. Terraform применяет план сразу, без показа пользователю списка изменений. В плане могут быть не только `create`, но и `destroy` / `-/+ replace` — как в этом шаге: старый контейнер молча удаляется и создаётся новый. Опасные сценарии:

- случайное удаление критичного ресурса из-за опечатки в конфиге (например, БД, диск, том);
- пересоздание ВМ с потерей данных на локальном диске;
- применение недосмотренного плана в production — без ревью и контроля.

**Зачем может пригодиться.**

- **CI/CD** (GitHub Actions, GitLab CI) — там нет интерактивного терминала, без флага пайплайн зависнет на `Enter a value`.
- **Автоматизированные тестовые окружения** — быстро развернуть/удалить без ручного участия.
- **Локальные/учебные сценарии**, когда план уже проверен глазами.

**Правило безопасности:** в production `-auto-approve` без предварительного `terraform plan -out=tfplan` (с ревью) использовать нельзя.

## Задание 1.7 — Почему образ `nginx:latest` не был удалён

### Ответ находится в коде

В `main.tf` в блоке `docker_image.nginx` есть строка:

```hcl
keep_locally = true
```

Именно она указывает провайдеру **не удалять локальный Docker-образ** при `terraform destroy`.

### Подтверждение из документации провайдера

Классификатор `resource docker_image` (registry.terraform.io/providers/kreuzwerker/docker/latest/docs/resources/image):

> **`keep_locally`** (Boolean) If true, then the Docker image won't be deleted on destroy operation. If this is false, it will delete the image from the docker local storage on destroy operation.

То есть:

- `keep_locally = true` → образ **остаётся** в локальном хранилище Docker после `destroy`;
- `keep_locally = false` (или параметр не указан) → образ **удаляется** при `destroy`.

Проверка, что образ на месте:

```bash
docker images | grep nginx
```

```
nginx    latest   b69ff87d4106   2 weeks ago   187MB
```
